# 에이전트를 정의한다는 것

## 어제 잘 굴러가던 팀이 오늘 아침 사라지는 이유

에이전트는 구두로 존재할 수 없다. 세션이 끝나면 아무것도 기억하지 않는다. 파일로만 존재한다. 에이전트 정의 파일은 **단순 설정 파일이 아니라 역할 계약서**이다. 에이전트 파일은 크게 두 부분으로나눌 수 있다.

- 프론트매터 5개 필드: name, description, model, tools, 선택필드
- 본문 7개 섹션: 핵심 역할, 작업 원칙, 입출력 프로토콜, 팀 통신 프로토콜, 에러 핸들링, 협업, 풀짐 자체 검증

## 본문 7개섹션

### 1. 핵심 역할 - 범위 결정

하는 일을 1~3개로 명시한다는 것은 **하지 않는 일도 함께 경계 짓는다**는 뜻이다. 범위가 모호하면 에이전트가 옆 에이전트의 영역까지 침범한다.

#### 나쁜 예

```markdown
## 핵심 역할
- 셰계관을 만든다.
```

#### 좋은 예

```markdown
## 핵심 역할
1. 세계의 물리 법칙과 기술 수준 정의
2. 사회 구조, 정치 체계, 경제 시스템 설계
3. 역사적 맥락과 현재 갈등 구조 수립
4. 장소별 환경과 분위기 묘사
```

### 2. 작업 원칙 - 판단 기준 결정

두 선택지가 충돌할 때 어느 쪽을 택할지 알 수 있어야 한다. 원칙이 추상적이면 실행할 때 마다 결과가 달라진다.

#### 나쁜 예

```markdown
## 작업 원칙
- 최선을 다한다.
- 품질을 높인다.
- 빠르게 작업한다.
```

#### 좋은 예

```markdown
## 작업 원칙
- PASS/FIX/REDO 3단계로 명확히 판정
- FIX는 부분 수정으로 해결 가능한 경우, REDO는 전면 재생성 필요
- 주관적 취향이 아닌 객관적 기준(일관성, 가독성, 구도)으로 판단
```

### 3. 입출력 프로토콜 - 에이전트 간 API 계약

다른 에이전트가 이 **에이전트의 산출물을 읽을 경로와 형식**을 정한다.

#### 나쁜 예

```markdown
## 핵심 역할
1. 세계의 물리 법칙과 기술 수준 정의
2. 사회 구조, 정치 체계, 경제 시스템 설계
...
```

#### 좋은 예

```markdown
## 핵심 역할
1. 세계의 물리 법칙과 기술 수준 정의
2. 사회 구조, 정치 체계, 경제 시스템 설계
...

## 입력/출력 프로토콜
- 입력: 사용자의 세계관 컨셉, 장르 요구사항
- 출력: '_workspace/01_worldbuilder_setting.md'
- 형식: 마크다운. 섹션별(물리/사회/기술/역사/장소)
```

### 4. 팀 통신 프로토콜 - 누구에게, 무엇을, 언제

주고 받을 정보의 세 요소(누구에게, 무엇을, 언제)를 명시한다. 팀 모드일때 의미가 있으며 단독으로 호출되는 서브 에이전트는 생략해도 된다. 메시지를 작성할때 기억할 원칙은 **좋은 메시지 = 발견 사실 + 수신자가 해야할 행동**이다.

#### 나쁜 예

```markdown
## 팀 통신 프로토콜
- 필요하면 다른 에이전트에게 메시지를 보낸다.
...
```

#### 좋은 예

```markdown
## 팀 통신 프로토콜
- character-designer에게: 사회구조, 계급 시스템, 직업군 정보 SendMessage
- plot-architect에게: 세계의 주요 갈등 구조, 위기 요소 SendMessgage
- science-consultant로부터: 과학적 오류 피드백 수신 -> 설정 수정
- 세계관 변경시 관련 팀원 전체에 브로드캐스트
```

### 5. 에러 핸들링 - 종료 조건 명시

구체적인 실패 시나리오, 각 시나리오에서의 행동, 최대 재시도 횟수를 정한다. 이것이 빠지면 에이전트는 예상치 못한 상황에서 무한대기하거나 잘못된 결과를 조용히 넘긴다.

#### 나쁜 예

```markdown
## 에러 핸들링
- 실패 시 재시도 한다.
```

#### 좋은 예

```markdown
## 에러 핸들링
- 이미지 로드 실패 시 해당 패널을 REDO로 판정
- 2회 재생성 후에도 REDO인 패널은 경고와 함께 PASS 처리
```

### 6. 협업 - 팀 안에서 위치 결정

누구와 어떤 순서로 연결되는지 명시한다.

```markdown
## 협업
- 상류: commit-message 스킬이 이 에이전트를 호출한다.
- 하류: commit-msg-reviwer가 이 에이전트의 draft를 읽는다.
- 재호출: reviwer 판정이 FIX/REDO일 때 스킬이 최대 2회까지 재호출한다.
```

### 7. 품질 자체 검증 - 제출 전 자기 점검

출력을 반환하기 전에 에이전트 스스로 거쳐야 할 체크리스트이다.

```markdown
## 품질 자체 검증(제출 전)

- [ ] 메타데이터 주석 포함
- [ ] 분량 2,500~4,000 단어 범위
- [ ] 파트별 포맷 필수 섹션 모두 포함
- [ ] 모든 수치, 인용에 출처 표기
- [ ] 용어 사전과 충돌 없음
- [ ] 코드 블록 컴파일/실행 가능
```
