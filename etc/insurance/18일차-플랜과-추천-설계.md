# 18일차. 플랜(설계안)과 추천 설계

> 5단계 상품과 프로세스 (전체 그림)

## 오늘의 목표

**정형 플랜과 자유 설계**의 차이를 이해하고, 추천 설계 로직이 어떤 원리로 동작하는지 감을 잡는다.

## 1. 두 가지 설계 방식

### 정형 플랜 (패키지 설계)

> 회사가 미리 만들어둔 **담보 조합을 그대로 선택**하는 방식.

```
[실속형]  월 26,000원
[표준형]  월 46,000원
[고급형]  월 82,000원
```

장점:

- 빠르다 (클릭 한 번)
- 위배가 없다 (검증된 조합)
- 설명이 쉽다
- 불완전판매 위험이 낮다

단점:

- 고객 개별 니즈 반영이 어렵다
- 불필요한 담보가 포함될 수 있다

### 자유 설계 (맞춤 설계)

> 담보를 **하나하나 선택하고 금액을 조정**하는 방식.

장점:

- 고객 맞춤
- 예산에 정확히 맞출 수 있다

단점:

- 시간이 걸린다
- 위배가 자주 발생한다
- 설계사 역량에 품질이 좌우된다
- 필요한 담보를 빠뜨릴 수 있다

### 실무는 혼합형

```
① 플랜 선택 (기본 골격)
        ↓
② 담보별 금액 조정
        ↓
③ 담보 추가/제외
        ↓
④ 위배 검증 및 해소
        ↓
⑤ 설계 확정
```

**"플랜으로 시작해서 자유 설계로 다듬는다"** 가 가장 일반적이다. 시스템도 이 흐름을 지원해야 한다.

## 2. 플랜 설계 시 고려사항

### 플랜 담보의 속성

플랜에 담긴 담보는 세 가지 성격으로 나뉜다.

| 속성 | 의미 | 예시 |
|---|---|---|
| **고정** | 제외 불가, 금액 변경 불가 | 주계약 |
| **금액변경가능** | 제외는 불가, 금액만 조정 | 암진단비 |
| **선택** | 제외 가능 | 치아보장 특약 |

```
플랜담보 (PLAN_COVERAGE)
  상품코드, 플랜코드, 담보코드,
  기본가입금액,
  제외가능여부,   ── Y/N
  금액변경가능여부, ── Y/N
  최소가입금액, 최대가입금액  ── 플랜 내에서의 범위 (상품 범위보다 좁을 수 있다)
```

### 플랜 보험료의 함정

플랜에 표시된 "월 46,000원"은 **특정 조건(예: 40세 남성 1급)에서의 금액**이다.

고객이 55세 여성 3급이면 완전히 다른 금액이 나온다. 그래서:

- 플랜 목록 화면에서는 **입력된 피보험자 기준으로 실시간 계산**해서 보여줘야 한다
- 대표 금액을 하드코딩해 두면 안 된다. 성능이 부담되더라도 계산해야 한다

## 3. 추천 설계의 기초

"이 고객에게 이런 설계를 권합니다"를 자동으로 만드는 기능이다.

### 추천의 입력값

| 분류 | 항목 |
|---|---|
| 인적 | 나이, 성별, 직업 |
| 가족 | 결혼 여부, 자녀 수, 부양가족 |
| 재정 | 소득, 예산(월 보험료) |
| 보유 | 기존 가입 계약 (자사/타사) |
| 니즈 | 관심 보장 영역 (암/실손/사망/노후) |

### 추천 로직의 접근법 세 가지

#### ① 룰 기반 (가장 흔함)

```
IF 나이 >= 40 AND 성별 = 여성
   THEN 유방암/자궁암 담보 우선순위 상향

IF 자녀 있음 AND 나이 30~50
   THEN 사망담보 가입금액 = 연소득 × 5배 제안

IF 기존 실손 보유
   THEN 실손 담보 제외

IF 직업급수 >= 3
   THEN 상해 담보 가입금액 상향 제안
```

장점: 설명 가능하고 통제 가능하다. 규제 산업에서 중요한 성질이다.

#### ② 갭 분석 기반

**필요보장액과 현재 보장액의 차이(gap)를 계산**해서 메운다.

```
필요 암 보장액 : 5,000만원 (치료비 + 소득상실 추정)
현재 보유      : 2,000만원
─────────────────────────
부족(GAP)      : 3,000만원  → 추천 가입금액
```

이 방식은 **고객에게 설명하기 좋다**. "왜 이 금액이냐"에 근거가 있다.

필요보장액 산출 기준 예시:

| 보장 | 산출 기준 |
|---|---|
| 사망 | (연소득 × 부양 기간) + 부채 - 자산 |
| 암 | 평균 치료비 + 소득 상실 1~2년치 |
| 실손 | 1인 1계약 (금액 개념 없음) |
| 입원일당 | 일 소득 × 0.5 정도 |

#### ③ 예산 역산

**"월 5만원에 맞춰줘"** 요청을 푸는 방식이다.

```
① 우선순위대로 담보 나열 (핵심 → 부가)
② 각 담보의 기준 가입금액으로 보험료 계산
③ 합계가 예산 초과 시:
   - 우선순위 낮은 담보부터 제외
   - 또는 가입금액을 비례 축소
④ 예산 미달 시:
   - 다음 우선순위 담보 추가
⑤ 위배 검증 → 해소 → 확정
```

여기서 중요한 것이 **담보 우선순위 테이블**이다.

```
담보추천우선순위
  상품코드, 담보코드, 우선순위,
  조건(성별/연령구간/자녀유무),
  기본가입금액산출식
```

## 4. 추천 설계 구현 시 주의사항

### ① 설명 가능해야 한다

```
❌ "AI가 추천한 최적의 설계입니다"
✅ "40대 남성 평균 대비 암 보장이 3,000만원 부족하여 추가 제안드립니다"
```

보험은 규제 산업이다. **불완전판매 책임**이 따르므로 추천 근거를 반드시 제시하고 저장해야 한다.

### ② 회사 이익을 위한 추천은 위험하다

수수료가 높은 담보를 우선 추천하도록 설계하면 **불완전판매·소비자 보호 위반**이 된다. 추천 로직의 우선순위는 **고객 니즈 기준**으로 설계되어야 하고, 그 근거를 문서화해야 한다.

### ③ 추천 결과도 반드시 위배 검증을 거친다

추천 엔진이 만든 조합이 규칙을 위반할 수 있다. 추천 → 검증 → 보정 흐름이 필요하다.

### ④ 추천은 초안일 뿐이다

최종 결정은 설계사와 고객이 한다. **추천값을 자유롭게 수정할 수 있어야** 하고, 수정 이력을 남긴다.

## 5. 시스템 관점

```
추천요청
  피보험자정보, 예산, 니즈코드, 기보유계약
        ↓
[1] 필요보장액 산출     ── 갭 분석
        ↓
[2] 담보 우선순위 결정   ── 룰 적용
        ↓
[3] 후보 담보 선정      ── 상품담보 + 인수조건 필터
        ↓
[4] 가입금액 배분       ── 예산 제약 하 최적화
        ↓
[5] 보험료 계산         ── 5, 6일차
        ↓
[6] 위배 검증           ── 16일차
        ↓
[7] 보정 (예산 초과/미달 시 재배분)
        ↓
추천결과 + 근거
```

### 데이터 모델

```
추천이력 (RECOMMENDATION)
  추천번호, 설계번호, 추천일시,
  입력조건(JSON), 추천결과(JSON), 추천근거(JSON),
  채택여부, 수정내역
```

**추천 이력을 남기는 이유:**

- 분쟁 시 "어떤 근거로 이 설계를 권했는가" 증빙
- 추천 로직 개선을 위한 데이터 (채택률, 수정 패턴)
- 규제 대응

### 성능

추천은 계산이 무겁다. 담보 후보 50개 × 금액 조합을 탐색하면 요율 조회가 수백 번 일어난다.

- 요율 캐싱 (6일차)
- 후보 담보를 먼저 강하게 필터링
- 금액 배분은 완전 탐색이 아니라 **휴리스틱**으로 (우선순위 순 그리디)

## 오늘의 정리

- **정형 플랜**은 빠르고 안전하지만 맞춤이 어렵고, **자유 설계**는 반대다
- 실무는 "플랜으로 시작 → 자유 설계로 다듬기" 혼합형
- 플랜 담보는 고정 / 금액변경가능 / 선택으로 나뉜다
- 플랜 보험료는 **피보험자 기준 실시간 계산**해야 한다
- 추천 방식: 룰 기반 / 갭 분석 / 예산 역산 — 실무는 셋을 조합한다
- 추천은 반드시 **설명 가능**해야 하고, **근거와 이력을 저장**해야 한다
- 추천 결과도 위배 검증을 거쳐야 한다
