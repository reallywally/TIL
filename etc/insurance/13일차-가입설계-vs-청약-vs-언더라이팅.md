# 13일차. 가입설계 vs 청약 vs 언더라이팅

> 4단계 언더라이팅 연결 (인수 심사와의 접점)

## 오늘의 목표

보험 가입 프로세스에서 **어디까지가 설계이고 어디서부터 심사인지** 경계를 그을 수 있게 된다. 각 단계의 산출물과 법적 성격을 구분한다.

## 1. 전체 프로세스 한눈에

```
[1] 상담/니즈 분석
        ↓
[2] 가입설계    ──> 산출물: 설계서(가입설계서, 상품설명서)
        ↓
[3] 청약        ──> 산출물: 청약서, 고지사항, 1회 보험료
        ↓
[4] 언더라이팅  ──> 산출물: 인수 판정 (승낙/조건부/거절)
        ↓
[5] 계약 성립   ──> 산출물: 보험증권
        ↓
[6] 계약 관리
```

각 단계의 성격이 완전히 다르다.

| 단계 | 법적 성격 | 주체 | 되돌릴 수 있나 |
|---|---|---|---|
| 가입설계 | 아무 구속력 없음 (안내) | 설계사/시스템 | 자유롭게 수정 |
| 청약 | **청약의 의사표시** | 고객 | 철회 가능(15일) |
| 언더라이팅 | 승낙 여부 판단 | 회사 | - |
| 계약 성립 | **계약 체결(승낙)** | 회사 | 해지/취소 |

## 2. 가입설계 — "이렇게 가입하면 이렇습니다"

### 무엇을 하는가

고객 조건(나이·성별·직업)과 니즈를 받아 **담보 조합과 가입금액을 정하고 보험료를 산출**한다.

```
입력: 피보험자 정보 + 원하는 보장 + 예산
  ↓
  담보 선택 → 가입금액 설정 → 규칙 검증 → 보험료 계산
  ↓
출력: 설계서 (보험료, 보장내역, 해지환급금 예시)
```

### 법적 성격

**아무런 구속력이 없다.** 설계서는 "안내 자료"일 뿐이다.

- 설계서의 보험료대로 반드시 가입되는 것이 아니다
- 회사가 인수를 거절할 수 있다
- 설계서를 뽑았다고 계약이 성립하지 않는다

다만 **설명의무의 근거 자료**가 되므로, 불완전판매 분쟁에서 중요한 증거가 된다. 그래서 설계서 출력 이력과 내용 보관이 필수다.

### 이 단계에서 검증하는 것 (자동)

9일차의 목록 그대로다.

- 연령·성별·직업 조건
- 가입금액 범위·배수
- 담보 간 관계 규칙
- **자사** 누적 한도
- 상품 단위 조건 (최저보험료 등)

### 이 단계에서 검증하지 않는 것

- 건강 상태 (아직 안 물어봄)
- 타사 계약 (동의 전이라 조회 불가)
- 재정 상태 (소득 증빙 없음)
- 도덕적 위험

## 3. 청약 — "이 조건으로 가입하겠습니다"

### 무엇을 하는가

고객이 **정식으로 가입 의사를 표시**하고, 심사에 필요한 정보를 제출한다.

```
① 청약서 작성 (설계 내용 확정)
② 고지의무 이행 (건강 상태 질문에 답변)
③ 각종 동의 (개인정보, 신용정보 조회, 피보험자 동의)
④ 1회 보험료 납입
⑤ 필요 서류 제출 (건강진단, 소득증빙 등)
```

### 법적 성격 — 여기서부터 진짜다

**청약은 계약 체결을 요구하는 의사표시**다. 법적 효과가 발생한다.

1. **책임개시**: 1회 보험료를 받은 시점부터 보험사의 책임이 시작된다. 심사 중에 사고가 나도 원칙적으로 보장된다(승낙 가능한 경우).
2. **청약철회권**: 청약일로부터 15일(또는 30일) 이내 철회 가능. 보험료 전액 환급.
3. **고지의무 발생**: 이 시점의 고지 내용이 계약의 전제가 된다.

### 설계와 청약의 차이 (핵심)

| | 가입설계 | 청약 |
|---|---|---|
| 건강 질문 | 없음 | **있음(고지의무)** |
| 동의 절차 | 없음 | **필수** |
| 보험료 납입 | 없음 | **1회 보험료 납입** |
| 회사 책임 | 없음 | **책임개시** |
| 수정 | 자유 | 정정·철회 절차 필요 |

## 4. 언더라이팅 — "받아줄지 판단합니다"

### 무엇을 하는가

회사가 **이 위험을 인수할지, 어떤 조건으로 인수할지** 판단한다.

```
청약 정보 + 고지 내용 + 진단 결과 + 타사 계약 조회
  ↓
  [자동심사] 룰 엔진이 판정 가능한 건은 즉시 처리
  ↓
  [수동심사] 언더라이터가 검토
  ↓
판정: 표준체 승낙 / 조건부 승낙(할증·부담보) / 거절 / 보류
```

### 무엇을 보는가

| 영역 | 내용 |
|---|---|
| **신체적 위험** | 병력, 현재 건강 상태, BMI, 흡연 여부, 가족력 |
| **환경적 위험** | 직업, 취미(스카이다이빙 등), 해외 체류 |
| **도덕적 위험** | 과도한 가입금액, 단기간 다수 가입, 보험금 청구 이력 |
| **재정적 위험** | 소득 대비 보험료, 소득 대비 보장금액 |

### 판정 결과

| 판정 | 의미 | 설계서 반영 |
|---|---|---|
| 표준체 승낙 | 그대로 가입 | 변경 없음 |
| 할증 승낙 | 보험료 더 받고 가입 | 보험료 증가 |
| 부담보 승낙 | 특정 부위/질병 제외하고 가입 | 보장 제외 조건 추가 |
| 감액 승낙 | 가입금액 줄여서 가입 | 가입금액 하향 |
| 일부 담보 거절 | 특정 담보만 제외 | 담보 삭제 |
| 전부 거절 | 인수 불가 | 계약 불성립 |
| 연기/보류 | 추가 자료 필요, 치료 완료 후 재심사 | 대기 |

15일차에서 자세히 다룬다.

## 5. 경계선이 흐려지는 지점

실무에서는 경계가 칼같이 나뉘지 않는다.

### 사전 인수 심사 (Pre-UW)

설계 단계에서 **간이 건강 질문**을 받아 미리 걸러내는 방식이 늘고 있다.

```
설계 화면에서:
  "최근 3개월 내 의사의 진찰·검사를 통해
   입원·수술·재검사를 권유받은 적이 있습니까?"
   → Yes면 설계는 되지만 "심사 필요" 표시
```

목적: **청약 후 거절되는 헛수고를 줄이는 것**. 설계사와 고객 모두의 시간을 아낀다.

### 간편심사 상품

고지 항목을 3~5개로 줄인 상품. 유병자도 가입 가능하지만 보험료가 비싸다. 이 경우 설계 단계에서 **일반심사 상품 vs 간편심사 상품** 선택 자체가 설계의 일부가 된다.

### 시스템적 시사점

설계 시스템은 **"이 건이 심사에서 문제가 될 가능성"을 미리 알려주는 역할**까지 하는 방향으로 발전하고 있다. 순수하게 금액만 계산하는 시스템이 아니다.

## 6. 시스템 관점 — 데이터의 흐름

```
설계 (DESIGN)
  설계번호(PK), 설계일자, 설계사, 상태,
  피보험자정보(임시), 담보목록, 보험료
      ↓ 전환 (convert)
청약 (PROPOSAL)
  청약번호(PK), 설계번호(FK), 청약일자,
  고지사항, 동의정보, 1회보험료,
  상태(접수/심사중/승낙/거절)
      ↓ 성립
계약 (CONTRACT)
  계약번호(PK), 청약번호(FK), 계약일, 책임개시일,
  담보목록(확정), 보험료(확정)
```

### 중요한 설계 원칙

1. **설계 데이터는 버려질 수 있다.** 설계는 수십 번 만들어지고 대부분 버려진다. 계약 테이블에 바로 쓰지 말고 **별도 영역**에 둔다. 보존기간 정책(예: 3개월)도 필요하다.

2. **설계 → 청약 전환 시 재검증.** 설계 시점과 청약 시점 사이에 보험나이가 바뀌거나(생일), 상품이 개정되거나, 다른 계약이 생겼을 수 있다. **전환 시점에 전체 규칙을 다시 돌려야 한다.**

3. **심사 결과로 내용이 바뀐다.** 부담보·할증·감액이 붙으면 청약 내용과 계약 내용이 달라진다. 원본과 변경본을 모두 보관하고, 고객 동의(재서명)를 받아야 한다.

4. **상태 관리가 핵심이다.** 청약 건은 접수→심사중→추가서류요청→승낙/거절로 흐르며, 각 상태에서 가능한 행위가 다르다. 상태 머신으로 명확히 정의해야 한다.

## 오늘의 정리

- **설계**는 안내 자료이며 구속력이 없다. 자동 검증 가능한 조건만 본다
- **청약**은 법적 의사표시다. 고지의무·동의·1회보험료·책임개시가 따라온다
- **언더라이팅**은 회사의 인수 판단이다. 건강·재정·도덕적 위험을 본다
- 설계는 "될 것 같은 것"을 보여주고, 심사는 "실제로 되는 것"을 정한다
- 사전 심사·간편심사로 경계가 흐려지는 추세
- 시스템은 설계/청약/계약을 분리 저장하고, **전환 시점마다 재검증**해야 한다

## 스스로 확인하기

1. 설계서를 받은 고객이 "이 보험료로 가입되는 거죠?"라고 물으면 뭐라고 답해야 하나?
2. 청약 후 심사 중에 사고가 나면 보장이 될까?
3. 설계 → 청약 전환 시 규칙을 다시 검증해야 하는 이유를 세 가지 들어보자.
