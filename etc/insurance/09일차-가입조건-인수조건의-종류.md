# 9일차. 가입조건(인수 조건)의 종류

> 3단계 가입조건과 규칙 (가입설계의 핵심)

## 오늘의 목표

"이 계약을 받아줄 수 있는가"를 판단하는 **조건들의 종류**를 파악하고, 각 조건이 설계 단계에서 어떻게 검증되는지 이해한다.

## 1. 가입조건이란?

보험사는 아무나, 아무 조건으로나 받아주지 않는다. **회사가 정한 인수 기준을 충족해야** 계약이 성립한다.

이 기준을 **가입조건** 또는 **인수조건**이라 부른다. 영어로는 Underwriting Rule / Acceptance Criteria.

가입조건은 두 층으로 나뉜다.

| 층 | 시점 | 판단 주체 | 성격 |
|---|---|---|---|
| **설계 단계 조건** | 가입설계 시 | 시스템(자동) | 객관적·기계적 판단 |
| **심사 단계 조건** | 청약 후 | 언더라이터(사람) + 시스템 | 건강·재정 등 주관적 판단 |

오늘은 **설계 단계에서 시스템이 기계적으로 검증하는 조건들**을 다룬다. 심사 단계는 4단계(13~16일차)에서 다룬다.

## 2. 가입조건의 종류

### ① 연령 조건

가장 기본이다. 담보마다 가입 가능 연령 범위가 다르다.

```
암진단비        : 만 15세 ~ 보험나이 70세
어린이 특약      : 0세 ~ 15세
치매진단비       : 40세 ~ 75세
운전자 벌금담보   : 만 19세 이상 (면허 필수)
```

주의할 점:

- **판정 기준은 보험나이**다 (6일차)
- **가입연령과 갱신연령이 다르다.** 신규 가입은 70세까지지만 갱신은 100세까지 가능한 식
- **만기 연령 제약**도 있다. "가입연령 + 보험기간 ≤ 100세"

### ② 금액 조건

가입금액의 최소·최대·배수 (2일차 참조)

```
암진단비 : 최소 1,000만원 / 최대 5,000만원 / 500만원 단위
입원일당 : 최소 1만원 / 최대 10만원 / 1만원 단위
```

최대값은 고정이 아니라 **연령·직업·소득에 따라 달라진다**. 11일차에서 자세히.

### ③ 직업 조건

특정 직업은 아예 가입이 안 되거나, 특정 담보만 제한된다.

```
5급 직업(고위험) : 상해담보 인수 불가
무직/학생        : 소득 관련 담보 제한
군인             : 일부 상해담보 제한
```

12일차에서 자세히.

### ④ 성별 조건

```
유방암·자궁경부암 담보 : 여성만
전립선암 담보         : 남성만
임신·출산 관련 담보    : 여성만
```

### ⑤ 기존계약 한도 조건

이 고객이 **이미 가진 계약**을 고려한다.

```
자사 보유 암진단비 합계 + 신규 가입금액 ≤ 자사 한도
자사 + 타사 합계 ≤ 업계 한도
```

11일차에서 자세히.

### ⑥ 담보 간 관계 조건

담보끼리의 조합 규칙 (부가필수/배타 등). 10일차의 주제다.

### ⑦ 상품 단위 조건

```
최저 보험료       : 월 2만원 이상이어야 청약 가능
주계약 필수 가입   : 주계약 없이 특약만 못 넣음
판매 기간         : 판매중지된 상품은 신규 불가
채널 제한         : 이 상품은 TM 전용 / GA 판매 불가
```

### ⑧ 피보험자 관계 조건

계약자와 피보험자가 다를 때의 규칙.

```
타인의 사망보험   : 피보험자 서면동의 필수 (상법 제731조)
미성년자 피보험   : 15세 미만은 사망담보 가입 불가 (상법 제732조)
부모-자녀 외 관계  : 피보험이익 확인 필요
```

**15세 미만 사망보장 금지**는 법률 강행규정이다. 시스템에서 반드시 막아야 하는 대표적 조건이다.

## 3. 조건 검증이 일어나는 순서

설계 화면에서 담보를 선택할 때 시스템은 이 순서로 검증한다.

```
① 상품 판매 가능 여부       (판매기간, 채널)
        ↓
② 피보험자 기본 자격        (연령, 성별, 관계, 동의)
        ↓
③ 담보별 가입 가능 여부      (연령, 성별, 직업)
        ↓
④ 담보 간 관계 규칙          (부가필수, 배타, 선택그룹)
        ↓
⑤ 가입금액 범위/배수         (최소, 최대, 단위)
        ↓
⑥ 누적 한도                 (자사 + 타사)
        ↓
⑦ 상품 단위 조건             (최저보험료, 주계약 필수)
        ↓
    → 통과: 설계 확정 가능
    → 위배: 위배 메시지 표시 (16일차)
```

이 순서가 중요한 이유: **앞 단계에서 걸리면 뒤 단계 검증이 무의미**하다. 예를 들어 연령 미달로 담보 자체를 못 넣는데 가입금액 한도를 계산할 이유가 없다. 성능과 메시지 품질 둘 다에 영향을 준다.

## 4. 조건의 종류를 나누는 다른 기준

### 하드 룰 vs 소프트 룰

| 구분 | 설명 | 예시 | 처리 |
|---|---|---|---|
| **하드 룰** | 절대 위반 불가 | 15세 미만 사망담보 | 설계 자체를 막음 |
| **소프트 룰** | 조건부 가능 | 한도 초과, 고위험 직업 | 경고 후 심사로 이관 |

시스템에서는 이 둘을 **다르게 처리**해야 한다. 하드 룰은 화면에서 차단, 소프트 룰은 "심사 필요" 표시 후 진행 허용.

### 자동판정 vs 수동판정

- **자동**: 나이, 금액, 코드 비교 → 시스템이 즉시 판정
- **수동**: 건강 상태, 재정 상태, 도덕적 위험 → 언더라이터 판단 필요

가입설계 시스템의 목표는 **자동판정 비율을 최대한 높이는 것**이다. 자동판정률이 곧 업무 효율이다.

## 5. 시스템 관점

가입조건은 보통 **룰 테이블**로 관리한다. 코드에 하드코딩하면 상품 하나 나올 때마다 배포해야 하므로 절대 안 된다.

```
담보가입조건 (COVERAGE_RULE)
  상품코드, 담보코드, 조건유형코드,
  조건값1, 조건값2,       ── 예: 최소연령=15, 최대연령=70
  성별구분,
  적용시작일, 적용종료일,
  위배구분(하드/소프트),
  위배메시지코드
```

핵심 설계 원칙 세 가지:

1. **조건은 데이터다, 코드가 아니다.** 새 상품·새 조건 추가 시 데이터만 넣으면 동작해야 한다.
2. **조건마다 위배 메시지를 붙인다.** "가입할 수 없습니다"가 아니라 "암진단비는 보험나이 70세까지 가입 가능합니다(현재 72세)"라고 나와야 한다.
3. **조건은 시점 관리가 필요하다.** 상품 개정으로 조건이 바뀌므로 적용기간 컬럼이 필수다.

## 오늘의 정리

- 가입조건은 **설계 단계(자동)** 와 **심사 단계(수동)** 로 나뉜다
- 주요 조건: 연령, 금액, 직업, 성별, 기존계약 한도, 담보 관계, 상품 조건, 피보험자 관계
- 15세 미만 사망보장 금지, 타인 사망 시 서면동의는 **법률상 강행규정**
- 검증에는 순서가 있고, 앞 단계 실패 시 뒤 단계는 무의미하다
- 하드 룰(차단)과 소프트 룰(경고 후 심사)을 구분해 처리한다
- 조건은 반드시 **룰 테이블(데이터)** 로 관리한다

## 스스로 확인하기

1. 12세 자녀를 피보험자로 하는 어린이보험에서 사망담보를 넣을 수 있을까?
2. "가입 불가" 한 줄 메시지가 왜 나쁜 설계인가?
3. 하드 룰과 소프트 룰을 시스템에서 다르게 처리해야 하는 이유는?
