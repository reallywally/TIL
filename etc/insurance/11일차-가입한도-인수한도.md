# 11일차. 가입한도(인수한도)

> 3단계 가입조건과 규칙 (가입설계의 핵심)

## 오늘의 목표

**가입한도**가 왜 존재하는지, 자사 한도와 타사 포함 한도가 어떻게 다른지, 한도 초과 시 어떻게 처리하는지 이해한다.

## 1. 가입한도란?

> 한 사람이 특정 담보에 대해 **가입할 수 있는 가입금액의 상한**.

2일차에서 구분했던 '한도'를 다시 보자.

| 용어 | 의미 | 정하는 주체 |
|---|---|---|
| 보장한도 | 약관상 지급 상한 | 약관 |
| **가입한도(인수한도)** | 받아줄 수 있는 가입금액 상한 | **회사(인수정책)** |

오늘은 뒤쪽이다. 영어로는 Underwriting Limit / Retention Limit.

## 2. 왜 한도가 필요한가

### ① 도덕적 위험(Moral Hazard) 방지

암진단비 5억원을 가입할 수 있다면? 보험금을 노린 범죄, 자해, 허위 진단의 유인이 생긴다. **보험금이 소득 수준을 크게 넘어서면 위험하다.**

### ② 역선택 방지

이미 증상이 있는 사람이 여러 회사에 대량 가입하는 것을 막는다.

### ③ 회사 리스크 관리

한 사람에게 지나치게 큰 위험이 집중되지 않게 분산한다.

## 3. 한도의 층위 — 가장 중요한 부분

한도는 **한 겹이 아니라 여러 겹**이다.

```
① 담보별 상품 한도      ── 이 상품에서 이 담보는 최대 얼마
        ↓
② 자사 누적 한도        ── 우리 회사 전체 계약 합산 최대 얼마
        ↓
③ 업계(타사 포함) 한도  ── 모든 보험사 합산 최대 얼마
        ↓
④ 소득 기반 한도        ── 연소득의 몇 배까지
```

### ① 담보별 상품 한도

```
A상품 암진단비 : 최대 3,000만원
B상품 암진단비 : 최대 5,000만원
```

상품 설계 시 정해지는 값이다. 2일차의 "가입금액 최대값"이 이것.

### ② 자사 누적 한도

**우리 회사에 이미 가입한 계약을 합산**한다.

```
기존 A계약 암진단비 3,000만원
기존 B계약 암진단비 2,000만원
─────────────────────────
자사 기가입 합계      5,000만원

자사 암진단비 한도    7,000만원
→ 신규 가입 가능액    2,000만원
```

이 계산을 위해 **피보험자 기준으로 기존 계약을 조회**해야 한다. 계약자 기준이 아니다. 같은 사람에게 위험이 집중되는지를 보는 것이므로 **피보험자 식별(주민번호/CI)** 이 기준이다.

### ③ 업계 한도 (타사 포함)

**다른 보험사의 계약까지 합산**한다.

```
자사 암진단비        5,000만원
타사 암진단비        8,000만원
──────────────────────────
업계 합계           13,000만원

업계 한도           15,000만원
→ 신규 가입 가능액    2,000만원
```

타사 정보는 어디서 오나?

- **신용정보원(KCIS) 조회**: 보험계약 정보를 집중 관리하는 기관. 조회하려면 고객 동의가 필요하다.
- **고객 고지**: 청약서에 기존 계약을 기재하게 한다.

**설계 단계에서는 타사 정보를 조회할 수 없는 경우가 많다.** 고객 동의 전이기 때문이다. 그래서 실무는 이렇게 흐른다.

```
설계 단계 : 자사 한도만 체크 + "타사 계약 있으면 심사 시 조정될 수 있음" 안내
       ↓
청약 단계 : 동의 받고 신용정보원 조회
       ↓
심사 단계 : 업계 한도 초과 시 감액 또는 거절
```

이 **시점 차이**를 이해하는 것이 오늘의 핵심이다.

### ④ 소득 기반 한도

사망보장·고액 담보에 주로 적용한다.

```
사망보험금 한도 = 연소득 × 10배
```

소득 증빙이 어려운 경우(주부, 학생, 무직)는 별도 기준을 둔다.

## 4. 한도 계산 시 주의점

### 담보 성격별로 합산 기준이 다르다

| 유형 | 합산 방식 |
|---|---|
| 진단비(정액) | 가입금액 단순 합산 |
| 입원일당 | 1일당 금액 합산 (예: 자사 3만 + 타사 5만 = 8만) |
| 사망 | 가입금액 합산, 소득 기준 별도 |
| 실손 | 합산 개념이 아님 → **중복가입 여부**만 본다 (3일차) |

### 유사 담보를 묶어서 본다

"암진단비", "고액암진단비", "특정암진단비"는 담보코드가 다르지만 **한도 관점에서는 같은 바구니**에 넣는다.

```
한도그룹: 암진단 계열
  ├─ 암진단비(유사암제외)
  ├─ 고액암진단비
  ├─ 특정암진단비
  └─ 재진단암진단비
```

이 그룹을 **한도그룹(한도코드)** 이라 부른다. 담보 하나하나가 아니라 그룹 단위로 한도를 관리하는 것이 표준이다.

### 소멸·실효 계약 제외

- 만기 소멸, 해지, 실효된 계약은 합산에서 제외
- 단 실효는 부활 가능성이 있어 회사마다 처리가 다르다
- 청약 접수 중(미성립) 계약도 합산 대상에 포함하는 것이 보통 → **가청약 단계 물량**을 놓치면 한도가 새어나간다

## 5. 한도 초과 시 처리

| 처리 | 설명 | 시점 |
|---|---|---|
| **차단** | 설계 자체를 막음 | 상품 한도 초과 시 |
| **자동 감액** | 가능 금액으로 자동 조정 | 자사 한도 초과 시 |
| **경고 후 진행** | 심사에서 판단하도록 넘김 | 타사 한도 미확인 시 |
| **심사 이관** | 언더라이터 판단 | 업계 한도 근접/초과 |
| **거절** | 인수 불가 | 명백한 초과 |

설계 시스템에서는 **"차단"과 "자동 감액"을 구분**하는 게 UX의 핵심이다.

- 차단: "암진단비는 이 상품에서 최대 3,000만원까지 가능합니다"
- 감액: "기가입 5,000만원으로 신규 가능액은 2,000만원입니다. 2,000만원으로 조정할까요?"

## 6. 시스템 관점

```
한도기준 (LIMIT_RULE)
  한도그룹코드,
  한도구분,        ── 상품한도 / 자사한도 / 업계한도 / 소득한도
  성별, 연령구간, 직업급수,
  한도금액,
  소득배수,
  적용시작일, 적용종료일

한도그룹담보 (LIMIT_GROUP_COVERAGE)
  한도그룹코드, 담보코드
```

### 한도 체크 API 설계

```
POST /limit/check
{
  "피보험자CI": "...",
  "담보목록": [
    {"담보코드": "C001", "가입금액": 30000000}
  ],
  "타사정보조회동의": false
}

응답
{
  "결과": "PARTIAL_OK",
  "항목": [{
     "담보코드": "C001",
     "한도그룹": "CANCER_DIAG",
     "상품한도": 50000000,
     "자사기가입": 50000000,
     "자사한도": 70000000,
     "가능금액": 20000000,
     "요청금액": 30000000,
     "판정": "EXCEED",
     "조치": "AUTO_REDUCE",
     "메시지": "기가입 5,000만원으로 2,000만원까지 가입 가능합니다"
  }]
}
```

포인트:

1. **판정 결과에 근거 숫자를 모두 담는다.** 고객·설계사에게 설명해야 하기 때문이다.
2. **피보험자 식별을 CI(연계정보)로 한다.** 이름+생년월일 매칭은 동명이인 문제가 있다.
3. **설계 시점과 청약 시점에 각각 체크한다.** 사이에 다른 계약이 성립했을 수 있다.
4. **성능**: 기가입 조회는 계약 전체 스캔이 되기 쉽다. 피보험자별 한도그룹 누적액을 **집계 테이블**로 유지하는 것이 일반적이다.

## 오늘의 정리

- 가입한도는 도덕적 위험·역선택·리스크 집중을 막는 장치다
- 한도는 **상품 → 자사 누적 → 업계(타사 포함) → 소득** 의 여러 겹이다
- 자사 한도는 설계 시점에 체크 가능하지만, **타사 한도는 동의 후 신용정보원 조회가 필요**해 심사 단계로 넘어간다
- 담보 하나가 아니라 **한도그룹** 단위로 관리한다
- 실손은 합산이 아니라 중복 여부를 본다
- 초과 시 차단 / 자동감액 / 심사이관을 구분해 처리하고, 판정 근거를 모두 보여준다
